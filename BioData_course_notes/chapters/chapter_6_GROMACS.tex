\chapter{GROMACS Tutorial: Self-Assembly of lipid bilayer with MARTINI FF}

MARTINI is a coarse-grained force field. In this tutorial, we simulate the self assembly of a lipidic bilayer membrane
in a water environment. 


\begin{figure}[H]
    \includegraphics[width=\textwidth]{practicals_img/gromacs/dspc_molecule.png}
    \caption{Di - Stearoyl - Phosphatidyl - Choline: It is a phospholipid, a natural constituent of cellular membranes.
    It features two stearic chains, and its head has both a phosphate group ($PO_4$) and a coline group ($N (CH_3)_4$).}
\end{figure}


The folder contains a lot of files. Let's navigate through them and understand what each contains.
There are basically $5$ extensions that you need to learn:

\begin{itemize}
    \item \textbf{.gro}: GROMACS structure files. Such files contain atomic or coarse-grained coordinates (positions, sometimes velocities)
    of your molecule.
    \item \textbf{.mdp}: stands for \textbf{M}olecular \textbf{D}ynamics \textbf{P}arameter file. These files contain simulation settings. For instance, \textbf{martini3.mdp} contains
    integrator type, timestep, temperature and pressure couplings, cutoffs. And \textbf{minimization.mdp} contains the settings for the energy minimization (method, number of steps). Files with 
    extension .mdp are passed as argument to gromacs command \textbf{grompp}.
    \item  \textbf{.itp/.top}: stands for \textbf{I}nclude \textbf{T}o\textbf{p}ology.  These files contain the actual force field definition, including all its parameters (bead types, bonded interactions terms, unbonded interactions).
    \item \textbf{.tpr}: while the preceeding files are text, this is instead a binary file, so it is not human readeable. It is generated by the gromacs command \textbf{grompp} and bundles everything GROMACS need to run a simulation,
    putting together information about topology, settings and structure. After creating the .tpr file, we can finally run the simulation with the gromacs command \textbf{mdrun}.
    \item \textbf{.trr, .tng, xtc}: trajectory files.
\end{itemize}


\section{A look at the provided files}

\begin{enumerate}
\item \textbf{dspc\_single.gro, water.gro}: configuration of a single molecule of DSPC and a single molecule of water, respectively;
\item \textbf{martini3.mdp}: settings for the use of the martini ff. These include integrator type, timestep, temperature and pressure couplings, cutoffs.
\item \textbf{minimization.mdp}: settings for the minimization step. These include minimization method and number of steps.
\item \textbf{martini\_v3.0.0.itp}: the file defining the core of the MARTINI force field.
\item \textbf{martini\_v3.0.0\_phospholipids\_v1.itp}: specifies how MARTINI represents phospholipids (in terms of coarse grained beads) and the force parameters.
\item \textbf{martini\_v3.0.0\_solvents\_v1.itp}: specifies how MARTINI represents and treats solvents.
\item \textbf{dspc.top, dspc\_noW.top}: these are c++ files that get passed on to the gromacs commands (e.g. grompp, mdrun). They call the .itp files from within. 
\end{enumerate}

\paragraph{Integration and outputs}
\begin{itemize}
    \item Integration algorithm: md (leap-frog).
    \item $dt=0.03$. time is expressed in picoseconds, so this is $dt=30\, fs$. 
    \item $nsteps=1.000.000$, so the total simulation time is $30\, ns$.
    \item output: $nstxout, nstvout, nstfout = 0$, no writing of full precision positions,velocities and forces.
    \item log file frequency $nstlog = 10.000$. One log file every ten thousand simulation steps. 
    \item compressed outputs: $nstxout-compressed = 1000$ write positions every $1000$ time steps, i.e. every $30 \,ps$.
    \item compressed precision ($1$/compressed-x-precision nm). In this case, $1/100\, nm$.
    \item energy calculation and output: energy is calculated every $nstcalcenergy$ steps, and written to file every $nstenergy$ steps.
    \item energy groups: $energygrps$ defines separate groups for the different molecules. In this case, interactions will be reported as DSPC-DSPC, DSPC-W, W-W.
\end{itemize}
\paragraph{Neighbour list and non-bonded interactions}


\paragraph{Temperature couplings}
\begin{itemize}
    \item tcoupl = v-rescale: activates the Bussi thermostat. This is widely recommended. Mantains the canonical ensemble correctly, and is stochastic.
    \item tc-grps = DSPC W: defines two separate couplings, one for lipid molecules and one for water. This is needed because d    ifferent components may exchange heat differently. This p    revents unphysical energy flow bias (e.g. solvent overheating lipids). 
    \item tau is the strength of the coupling. Expressed in picoseconds. It is the relaxation timescale. Smaller tau, stronger coupling. In this case, both water and
    lipid will reach target temperature in $\tau = 1\, ps$, which corresponds to $\simeq 33$ simulation steps. 
    \item ref\_t: target temperature. In this case, $323\, K$, or $50$ degrees celsius.
\end{itemize}

\section{The simulation workflow}

\subsection{Setup}
\begin{figure}[H]
  \centering
  \includegraphics[width=0.7\textwidth]{gromacs_img/system_setup.png}
  \caption{The steps involved in the preparation of the system, prior to the simulation. There are
  two minimization steps: first, minimize the lipid molecules only, second, minimize again with the solvent.}
\end{figure}


\begin{verbatim}
  gmx insert-molecules -ci dspc_single.gro -nmol 128 -box 7.5 7.5 7.5
  -try 500 -o 128_noW.gro
\end{verbatim}

Takes as input the coordinate file dspc\_single.gro, which contains a single DSPC molecule, and attempts to place $128$ copies
(-nmol $128$) into a cubic box of dimensions $7.5 \times 7.5 \times 7.5$ nm (-box $7.5$ $7.5$ $7.5$). The -try $500$ option sets the maximum number of insertion attempts per molecule to avoid steric overlaps.
The resulting structure is written to the output file 128\_noW.gro.


\begin{verbatim}
gmx grompp -f minimization.mdp -c 128_noW.gro
 -p dspc-noW.top -o dspc-min-init.tpr
\end{verbatim}


Generate a portable binary run file for simulation. Specifically, \texttt{gmx grompp} reads the molecular dynamics parameters from \texttt{minimization.mdp} (\texttt{-f}),
which typically defines an energy minimization protocol, and combines them with the initial configuration \texttt{128\_noW.gro} (\texttt{-c}) and the system topology \texttt{dspc-noW.top} (\texttt{-p}),
which encodes molecular structure, force field parameters, and connectivity. The output is a binary input file \texttt{dspc-min-init.tpr} (\texttt{-o}),
containing all necessary information (coordinates, parameters, and topology) required by the GROMACS engine to perform the subsequent energy minimization step. Then, to effectively run the minimization:

\begin{verbatim}
gmx mdrun -deffnm dspc-min-init -v -c 128_minimised.gro
\end{verbatim}

Here, the \texttt{-deffnm} flag sets \texttt{dspc-min-init} as the default file name for both the input (which is \texttt{dspc-min-init.tpr}),
created at the previous step, and the outputs that are going to be created. Flag \texttt{-v} just stands for verbose, and \texttt{-c} for configuration.
The output of this energy minimization was:

{
  \small
\begin{verbatim}
-----------------------------------------------------------------------------
Energy minimization reached the maximum number of steps before the forces
reached the requested precision Fmax < 10.

writing lowest energy coordinates.

Steepest Descents did not converge to Fmax < 10 in 1001 steps.
Potential Energy  = -2.1029334e+04
Maximum force     =  1.9983762e+02 on atom 711
Norm of force     =  7.8412237e+00
-----------------------------------------------------------------------------
\end{verbatim}
}
It is not generally a problem if the steepest descent does not converge. You don't really need
to get exactly to the minimum, but just to get to a state that is stable enough that your system doesn't 
undergo huge accelerations in the first few steps of the simulation. Before moving forward, we could inspect the 
coordinates files and compare the before and after minimization. A nice trick: you can type \texttt{vimdiff 128\_*}. This opens a split vim 
editor with the two files, and the columns that differ are highlighted in red. 

Also, since the verbose option prints out the energy trend step after step, you can copy paste that output in a new file, open it in \texttt{vim},
delete the columns that you dont need (enter visual block mode with control + v), save, exit, then plot it with gnuplot by writing
\texttt{plot "file.txt" w l}.  


Now we add the water molecules to the box:

\begin{verbatim}
  gmx solvate -cp 128_minimised.gro -cs water.gro -o waterbox.gro
   -maxsol 1000 -radius 0.21
\end{verbatim}

Here, \texttt{-cp} is the configuration of the protein, \texttt{-cs} the configuration of the solvent,
\texttt{-maxsol} the number of solvent molecules to add, \texttt{-radius} is the radius to assign to the solvent beads.
Here it is specified manually. If you don't, GROMACS will look it up on its internal tables, but it may produce clashes. 




\subsection{Equilibration run}

To prepare the new .tpr file type
\begin{verbatim}
gmx grompp -f martini3.mdp -p dspc.top -c minimised.gro -o dspc-eq.tpr
\end{verbatim}


Now we can run the simulation by typing
\begin{verbatim}
 gmx mdrun -deffnm dspc-eq -v
\end{verbatim}

\paragraph{While it runs...}
This step can be quite lengthy, and depending on the amount of available cores it might take several minutes (GROMACS should provide an estimate of the remaining time). To make sure that the simulation behaves as expected, you can use VMD to check the trajectory visually while it is still running, e.g., in a separate terminal, type:
\begin{verbatim}
vmd minimised.gro dspc-eq.xtc
\end{verbatim}
If you want, you can also inspect the .tpr file. It is binary, but it can be made human
readeable with the command \texttt{gmx dump -s dspc-eq.tpr}. There are some interesting things
worth noticing in there. It is a very long file, that contains all the aggregated information from the
structure and topology files. For example, it contains the pressure tensor:


{
  \small 
\begin{verbatim}
   tau-p                          = 6
   compressibility (3x3):
      compressibility[    0]={ 3.00000e-04,  0.00000e+00,  0.00000e+00}
      compressibility[    1]={ 0.00000e+00,  3.00000e-04,  0.00000e+00}
      compressibility[    2]={ 0.00000e+00,  0.00000e+00,  3.00000e-04}
   ref-p (3x3):
      ref-p[    0]={ 1.00000e+00,  0.00000e+00,  0.00000e+00}
      ref-p[    1]={ 0.00000e+00,  1.00000e+00,  0.00000e+00}
      ref-p[    2]={ 0.00000e+00,  0.00000e+00,  1.00000e+00}
\end{verbatim}
}
$\tau_p = 6\,\mathrm{ps}$ is the relaxation time of the barostat, i.e.
 how quickly the system volume adapts to the target pressure. Larger values imply slower, smoother equilibration.
The compressibility tensor defines the compressibility of the system. Here, isotropic (equal values in all directions)
with zero off-diagonal terms, so there is no coupling between different spatial directions.
Then we have the reference pressure tensor (ref-p). This defines the target pressure imposed by the barostat.


\paragraph{When it is done}you will have these output files:
\begin{itemize}
  \item dspc-eq.tpr (full trajectory)
  \item dspc-eq.xtc (compressed trajectory)
  \item dspc-eq.edr (energy file, binary)
  \item dspc-eq.log (log file)
  \item dspc-eq.cpt (checkpoint file, binary): if accidentantly your simulation breaks halfway through, you can restart it from the last frame using this checkpoint file, which contains the positions \textit{and velocities} 
  of all particles. You can also use this file to extend the simulation further, beyond the original temporal range.

\end{itemize}

\subsection{Production run}
We do not want our analyisis be influenced by the equilibration phase, so we use the end point of our first simulation, the equilibration run, for a new simulation, i.e., the production run. The resulting trajectory will be used to analyse the properties of the bilayer. The choice of the simulation time depends on the observable of interest, the available resources, and the desired sampling. It should be long enough to obtain meaningful averages of those properties.
You may adapt it via the number of steps in the “.mdp” file.  Type:

\begin{verbatim}
  gmx grompp -f martini3.mdp -p dspc.top -c dspc-eq.gro -o dspc-pr.tpr
  gmx mdrun -v -deffnm dspc-pr
\end{verbatim}

\paragraph{6. Order parameter}
Here $\theta$ is the angle formed between the bond vector and the perpendicular to the layer surface. 
\begin{figure}[H]
  \includegraphics[width=0.8\textwidth]{gromacs_img/order_param_calc.png}

\begin{align*}
\langle \cos^2 \theta \rangle &=
\begin{cases}
1      & \text{bond is perpendicular to surface} \\
\frac{1}{3} & \text{random} \\
0      & \text{bond is parallel to surface}
\end{cases} \\[1em]
\langle P_2 \rangle &=
\begin{cases}
1    & \text{bond is perpendicular to surface} \\
0    & \text{random} \\
-0.5 & \text{bond is parallel to surface}
\end{cases}
\end{align*}
